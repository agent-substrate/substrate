# apivalidation

See `docs/api-validation.md` for how declarative validation (DV) works in Substrate, its limitations, and best practices.

- `zz_generated.validation.go` is generated by `hack/update/codegen.sh`. Never edit it by hand.
- Every `ateapipb` message whose name ends in `Request` gets generated validation from its DV tags.
- Validation code only: generated DV code, custom validators, and thin exported shims that callers such as RPC handlers use.
- One file per resource. Shared validation and messages go in `common.go`.
- Tests cover exported functions only, with one table-driven test per exported function that covers all of its cases.
- Run `go test -cover` (or `-coverprofile`) to check that every path is covered, both valid and invalid inputs.
