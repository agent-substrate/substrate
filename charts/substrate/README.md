# substrate

Helm chart for installing Agent Substrate.

The chart uses mTLS and requires a prepared PostgreSQL database. It requires the
`ClusterTrustBundle`, `ClusterTrustBundleProjection`, and
`PodCertificateRequest` feature gates plus the `certificates.k8s.io/v1beta1`
API.

Install the [certificate controller](../substrate-podcert/README.md) as a separate
release before preparing PostgreSQL or installing this chart. One controller
serves the cluster; the application chart does not deploy it.

```bash
# CRDs
helm upgrade --install substrate-crds ./charts/substrate-crds

# Create CA pools, then install their certificate controller
go run ./cmd/ate-setup create podcertificate-controller-cas
helm upgrade --install substrate-podcert ./charts/substrate-podcert \
  --namespace podcertificate-controller-system --create-namespace --wait

# Install Substrate after creating the database identities and Secrets
helm upgrade --install substrate ./charts/substrate \
  --namespace ate-system --create-namespace \
  --set postgres.readWriteConnectionStringSecretRef.name=substrate-postgres-readwrite \
  --set postgres.ownerConnectionStringSecretRef.name=substrate-postgres-owner
```

By default, component images are pulled from `ghcr.io/kagent-dev/substrate`
using the chart `appVersion` as the tag. Override `image.registry` and
`image.tag` to install from a different image repository or tag.

The chart installs the Kubernetes credential provider and enables HTTPS egress
interception. Create the `egress-mitm-ca-pool` Secret and configure actor trust
as described in the [credential provider setup](../../docs/kubernetes-credential-provider.md).
Namespace grants default to an empty list, denying credential access.

This chart installs atelet by default. To upgrade atelet on its own schedule,
set `atelet.enabled=false` and install the
[substrate-atelet](../substrate-atelet/README.md) chart as a second release.

## Render manifests without applying

```bash
helm template substrate ./charts/substrate
```

`manifests/ate-install/` in the repo is the rendered mTLS output and is
regenerated by `hack/render-manifests.sh`. The separate `substrate-crds` chart
mirrors `manifests/ate-install/generated/`.

## Values

See `values.yaml` for the full set; the important keys:

| Key | Default | Notes |
|-----|---------|-------|
| `postgres.readWriteConnectionStringSecretRef` | `substrate-postgres-readwrite` | Read the read/write connection from a pre-created Secret |
| `postgres.ownerConnectionStringSecretRef` | `substrate-postgres-owner` | Read the owner connection from a pre-created Secret |
| `postgres.readWriteRole` | `substrate_readwrite` | Role assumed by read/write connections |
| `postgres.ownerRole` | `substrate_owner` | Role assumed by owner connections |
| `preview` | `[]` | Preview gates for the API server, controller and workers, and atelet; set `[ExternalVolumes]` to enable external volume APIs and mounts |
| `postgres.schema` | `substrate` | Store the Substrate tables in this PostgreSQL schema |
| `postgres.clientCertificates.enabled` | `false` | Project separate owner and runtime login certificates into the API server |
| `<component>.resources` | see `values.yaml` | Requests and limits for each container, e.g. `ateApi.resources` and `atenetRouter.agentgateway.resources` |
| `rustfs.enabled` | `true` | Deploy an in-cluster S3-compatible RustFS bucket for snapshots |
| `ateApi.snapshotLocation` | `""` | Cluster-wide snapshot URI; defaults to `gs://<rustfs.bucket>/` with bundled RustFS |
| `atelet.enabled` | `true` | Set to `false` to install atelet with the [substrate-atelet](../substrate-atelet/README.md) chart and upgrade it separately |
| `atelet.storageBackend` | `s3` | Default snapshot backend, wired to RustFS when `rustfs.enabled=true` |
| `atelet.imageCredentialProviderConfig` | `""` | Host path to the kubelet credential provider config; set together with the bin directory |
| `atelet.imageCredentialProviderConfigYAML` | `""` | Credential provider config as text, rendered into a ConfigMap, for nodes where that file cannot be authored or must differ from the kubelet's; mutually exclusive with the host path |
| `atelet.imageCredentialProviderBinDir` | `""` | Host path to the kubelet credential provider binaries; both paths are mounted read-only |
| `credentialProvider.namespacePolicies` | `[]` | Default-deny atespace-to-namespace grants; the chart includes get-only Secret RBAC for the provider |
| `ateApi.actorJWTIssuer` | `https://<idp-service>.<namespace>.svc` | Issuer placed in actor JWTs; set a stable URL reachable by relying parties |
| `objectStorePlugin.extraEnv` | `[]` | Object storage credentials/settings shared by both object-store plugins |
| `objectStorePlugin.control.resources` / `objectStorePlugin.node.resources` | see `values.yaml` | Resources for the API and node object-store sidecars |
| `ateApi.logLevel` | `info` | API server log level in its mounted config; one of `debug`, `info`, `warn`, or `error` |
| `ateApi.authorization.bootstrapOwners` | `[]` | Global owners; empty defaults to the release's shared `ate-client` ServiceAccount |
| `ateApi.extraArgs` | `[]` | Additional command-line arguments appended to the ateapi defaults |
| `otel.endpoint` | `""` | Set to an OTLP endpoint to export traces, metrics, the actor lifecycle events and the router access log |
| `otel.traces.enabled` | `true` | Set to `false` to export no traces from the router; the Go components do not honor this yet |
| `otel.traces.endpoint` | `""` | OTLP endpoint for traces, overriding `otel.endpoint` |
| `otel.traces.samplingRatio` | `0.01` | Fraction of parentless requests that start a trace, applied to the Go components and the router |
| `otel.metrics.enabled` | `true` | Set to `false` to disable OTLP metrics push; Prometheus scraping remains available |
| `otel.metrics.endpoint` | `""` | OTLP endpoint for metrics, overriding `otel.endpoint` |
| `otel.logs.enabled` | `true` | Enable OTLP actor events from ateapi and the ateworkers, plus the router access log. Actor events go to stdout when OTLP logs are disabled |
| `otel.logs.endpoint` | `""` | OTLP endpoint for logs, overriding `otel.endpoint` |

## Upgrading sandbox and snapshot configuration

Public APIs now use versioned packages under `api/`. Upgrade clients, control
plane, workers, credential providers, object-store plugins, and agentgateway
together: gRPC service names now start with `substrate.<api-name>.v1`.

WorkerPool, SandboxConfig, and CSIDriverConfig resources now use `ate.dev/v1`.
Update custom manifests and install `substrate-crds` before the application
chart. Existing clusters need a storage-version migration before replacing the
old CRDs: Kubernetes rejects the v1-only definitions while `status.storedVersions`
still contains `v1alpha1`. This release does not provide a conversion webhook or
an automated migration. Back up existing resources and plan their migration
before upgrading.

External volumes now require `preview: [ExternalVolumes]` and a client that opts
in to the same gate (for `kubectl ate`, pass `--preview=ExternalVolumes`).
Actor and ActorTemplate container resource limits must include positive CPU and
memory values. Worker images are now named `ateworker-gvisor` and
`ateworker-microvm`; update custom WorkerPools and image mirrors accordingly.

Upgrade `substrate-crds` before the application chart. Custom `SandboxConfig`
resources now put assets under `spec.versions[]`, with a named
`spec.defaultVersion`. Remove `pauseImage` from custom configs; gVisor no longer
uses a pause container. WorkerPools select the runtime through
`spec.sandboxClasses[]`; remove `sandboxConfig` from actor templates.

WorkerPools now resolve `spec.sandboxClasses[].configRef` or the class default
before creating their worker Deployment. Ensure each pool names an existing
config of the same class, or that one is annotated
`sandboxconfig.ate.dev/is-class-default: "true"`. The chart supplies that
annotation on `gvisor-default`. Sandbox class names are immutable; create a
new pool to change runtime families. Configs referenced by a pool are protected
from deletion until the pool switches configs or is deleted.

Update API clients for the simplified snapshot model: `Snapshot.uuid`,
`fidelity`, `locality`, and `durableSnapshot` replace the `storage[]` entries,
and durable snapshot status uses `PENDING` instead of `IN_PROGRESS`. The proto
field numbers changed, so upgrade clients and components together.
Persisted Actor and Tag snapshot metadata uses the same protobuf schema and
is not migrated by this update. For development installs, delete affected
Actors and Tags with the old version, then recreate them after upgrading.

Snapshot transfers now run in `objectstore-plugin` native sidecars in the
API server and atelet pods. Rename existing `snapshotPlugin` Helm settings
to `objectStorePlugin`. Move external object storage environment settings from
`atelet.extraEnv` or the API environment ConfigMap to
`objectStorePlugin.extraEnv`, so both plugins receive them. The node plugin also
downloads private sandbox assets into an isolated staging volume before
verifying and publishing them. `ATE_STORAGE_BACKEND` must not be set on the
API server or atelet itself; select it through `atelet.storageBackend`.
RustFS is wired automatically. Private S3 asset URLs must use `s3://`.

GCS snapshot transfers now require `objectStorePlugin.transferServiceAccount`,
the email of a dedicated Google service account. Grant it object access to the
snapshot bucket, and let the API server's identity impersonate it. See
[the GCP setup guide](../../tools/setup-gcp/README.md#what-create-iam-actually-grants)
for the required IAM grants. S3 and RustFS do not need this setting.

The default gVisor config now uses release `20261026.0` (`v6`) for separate
container-rootfs and durable-directory checkpoint bundles. Upgrade the sandbox config together with ateworker-gvisor;
custom configs must pin a release with the same checkpoint support and supply
the `gvisor` release tarball asset. Bare `runsc` assets are no longer accepted.
This replaces the previous `v5` config. Existing `v5` memory snapshots need a
compatible runtime; falling back to a durable filesystem snapshot does not
restore the actor's memory.

The [image cache](../../internal/imagecache/README.md) now uses layout version 3
to preserve image ownership and permissions. Atelet refuses version 2 caches.
Stop the actors on each node before deleting its old image cache
(`/var/lib/ate/image-cache` by default). Atelet recreates it on startup.

When upgrading an installation with RustFS enabled, delete its completed bucket
initializer Job before running `helm upgrade`. The default Job name is
`rustfs-bucket-init` in the release namespace. This update changes the AWS CLI
image, and Kubernetes cannot patch an existing Job's pod template. Helm
recreates the Job, which keeps the existing bucket and its contents.

The router now requires mTLS on ports 8443 and 8444. Set
`atenetRouter.ingressAllowedSPIFFEIDs` to the client identities allowed to reach
actors; its empty default denies all ingress. Plaintext ports 8080 and 8081
no longer accept connections.

The chart now denies ingress to the control-plane namespace by default and
allows the component, router, egress, storage, and monitoring traffic it needs.
Label namespaces containing API clients with `ate.dev/api-access=true`; worker
pods remain excluded from that client allowance. Custom workloads sharing the
control-plane namespace need their own ingress policies. Custom health probes
for the API server, atelet, and credential provider must use port 9091;
port 9090 serves metrics only.

Update API clients for pagination under `ListOptions`, the renamed
`MintActorJwt` RPC and TitleCase protobuf type names, `WakeupProbe`, and the
`*_time` timestamp fields. Pausing now transitions through `SUSPENDING` to
`SUSPENDED`; use snapshot locality to distinguish a paused actor. Upgrade
clients and components together.

## PostgreSQL setup

Upstream squashed the migrations through v0.6.0 into `000001_initial.sql`.
Databases created before that squash cannot be upgraded in place and must be
recreated. See [PostgreSQL schema evolution](../../docs/dev/postgresql-schema-evolution.md).

The chart does not deploy or initialize PostgreSQL. Prepare the database,
schema, login users, and the configured `readWriteRole` and `ownerRole` before
installing the chart. For development Helm installations in `ate-system`,
run `hack/install-postgres.sh` after installing the separate certificate
controller and its CA pools. It deploys certificate-protected PostgreSQL,
runs the shared bootstrap SQL, and creates both connection Secrets. Use `--kind`
for the smaller Kind deployment; set `KUBECTL_CONTEXT` to select a cluster.
Standalone manifest installations can continue to use `ate-setup`.

When using `hack/install-postgres.sh`, install the application chart with
`--set postgres.clientCertificates.enabled=true`. Its connection Secrets use
the projected owner and runtime certificates. For external databases using
password or provider-managed authentication, leave this setting disabled.
Service-DNS and pod-identity certificates remain enabled for Substrate's
internal connections. Standalone manifest generation enables the PostgreSQL
certificates for the bundled development database.

For an operator-managed database, the operator must provision the identities,
schema, and grants, and create both connection Secrets in the release namespace.

Substrate runs `SET ROLE` for each new connection. It rejects a login without
the required membership.

Create both group roles and all grants before installation, then set
`postgres.readWriteRole` and `postgres.ownerRole` to those names. Use distinct
roles and table schemas for separate installs sharing one database. Give each
install separate logins and grant each login membership only in its install's
roles.

## Upgrading API configuration and authorization

The API server now requires `--config-file`. The chart mounts its generated
`ate-api-config` ConfigMap and rolls the API pods when `ateApi.logLevel` changes.
Replace `--log-level` in `ateApi.extraArgs` with `ateApi.logLevel`.

API authorization is always enforced, matching `ate-setup`. Remove
`ateApi.authorization.enabled` from custom values. The release's
shared `ate-client` ServiceAccount is a bootstrap global owner so demos and
CLI access work. For shared installs, set `ateApi.authorization.bootstrapOwners`
to your operators' own principals and grant tenant access with `kubectl ate
create access-policy`; anyone who can mint the shared client's token otherwise has
global owner access. See [authorization](../../docs/guides/authorization.md).

Upstream renumbered protobuf fields, so older clients and binaries are not
wire compatible. Upgrade clients and components together: upstream now uses the
`go.ate.dev/substrate` Go module, and the worker protocol includes dynamic
runtime registration and the unified suspend/pause workflow. Custom worker
images and integrations must use the matching API version.

The pinned agentgateway image includes the updated `Actor.status`, actor-state,
and `MintActorJwtRequest` bindings. If you override `images.agentgateway`, use
these bindings too; older images cannot resolve actor routes or mint actor JWTs
against this API.
The image also preserves the requested actor port across HTTP/1 and HTTP/2
CONNECT tunnels.

Every checkpoint requires an object-storage URI, including a pause that
keeps its snapshot local. The chart sets the cluster-wide snapshot location
from `rustfs.bucket` for bundled storage; external storage installs must set
`ateApi.snapshotLocation`. Actor templates inherit this location. Existing
`snapshotConfig.storageLocation` overrides require the
`PerTemplateSnapshotLocation` preview gate; remove those overrides when using
the cluster default without the gate. Upgrade the API server, atelet, and
workers together for checkpoint validation and per-actor sandbox asset paths.

`DeleteActorRequest.any_state` and the CLI's `--any-state` flag are removed;
actors can now be deleted in any state. Atelet's TLS listener now accepts only
the API server's SPIFFE identity and no longer exposes a host port. The chart
configures that identity for the release namespace and service account.

The `ate-idp-server` binary serves actor JWT discovery and public signing keys
over HTTPS. The chart deploys it behind the `idp` Service (prefixed with the
release name for non-default releases) and permits HTTPS discovery traffic.
The default actor JWT issuer points at this Service; external consumers need
an externally reachable issuer URL and routing to it.

Atelet now listens on TCP port 21998; update external firewall rules that
allowed port 8085. Replace `PauseActor` calls with
`SuspendActor` and `options.mode: DURABILITY_MODE_ASYNCHRONOUS`.
`SuspendActor` defaults to asynchronous durability; callers that require an
external snapshot before returning must request `DURABILITY_MODE_SYNCHRONOUS`.
